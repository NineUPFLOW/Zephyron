# Как работать над Zephyron

Правила, выведенные из практики. Каждое стоило времени, поэтому записано
не «как надо», а почему именно так.

## Ветки и выпуск

- **Основную ветку не трогать без прямой просьбы владельца.** Вся работа —
  на ветке, названной владельцем (сейчас `test`). Основная — `zephyron`.
- **Выпуск — только по «релизь X.Y.Z».** «Переименуй в X.Y.Z» — только номер,
  не выпуск. Релизить целиком, а не переспрашивать, но и не по своему почину.
- Релиз — ручной: `.github/workflows/release.yml`, `workflow_dispatch`, ref
  `zephyron`. Триггер только `workflow_dispatch`: `gh release create` сам
  ставит тег, и `push: tags` поднимал бы второй прогон с красным крестом.
- `build.yml` — push в main/zephyron и PR: только сборка и тесты.
- Версия — `<Version>` в `Directory.Build.props`.

## Сборка

- Окно и `zy` собирает `build.cmd` в `build\`; консоль удалена 23.09.
  Сборка идёт из `build\`, а не из `bin\`: MSBuild пишет в каталог с загруженными
  сборками, и пересборка падает, пока программа запущена.
- **Единый файл — только `pack.cmd` (или CI).** Голый `dotnet publish` без
  `-p:IncludeNativeLibrariesForSelfExtract=true` даёт архив без нативных частей
  .NET: программа молча выходит без окна (так вышли 0.15.7/0.15.8).
  Рабочий файл ~172 МБ, сломанный ~160.
- Windows в контейнере не поднять: запуск единого файла вручную не проверить —
  только размер и отсутствие разбросанных `*_cor3.dll`.

## Тесты

- Два набора: `tests/Zephyron.Core.Tests` (в `Zephyron.sln`) и
  `tests/Zephyron.Gui.Tests` (в `gui/Zephyron.Gui.sln`, WPF).
- **На Linux `Zephyron.Gui.Tests` только собираются** — testhost падает.
  `Zephyron.Core.Tests` дают **33 падения** — базовый уровень (пути `C:\`,
  процессы, планировщик, реестр, robocopy), не регрессия.
- Разметка проверяется текстом (`ResourceKeyTests`, `DesignTokensTests`,
  `BindingPathTests`, `ChevronTests`, `UpdateWindowTests`): ссылки
  `{StaticResource}` против ключей темы, токены против `docs/design-system.md`,
  «геометрический токен не несёт числа», привязки против свойств типов.

## Оформление

- **Источник правды — макет владельца `docs/design/mockup.html`.** Других
  описаний дизайна не искать и не выдумывать: макет и есть договор оформления.
- Слоты темы — **ровно 14** (`theme.json`, чужие темы знают столько).
  Цвета сверх слотов выводятся в `Themes.Build` и объявлены теми же ключами
  в `Palette.xaml` (тест `ABuiltThemeHasEveryKeyOfTheXamlPalette`).
- Имена элементов и обработчики окна менять нельзя без правки кода: `Rail`,
  `RailStatus`, `Section`, `Mark`, `Toast*` и прочие ищутся в `MainWindow.xaml.cs`.
- Анимации — через `Motion` (`Motion.Enabled` учитывает и выключатель
  в «Оформлении», и системную настройку).

## Память

- **`AGENTS.md` — память проекта.** Всё, чему учусь (грабли, замеры, решения
  владельца, разборы), записываю сюда сам. Проверенное вживую — отдельно
  от догадки. Владелец может очистить память — тогда писать заново.
